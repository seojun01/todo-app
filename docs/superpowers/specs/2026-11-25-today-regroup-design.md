# 오늘 화면 재구성 (묶음 + 오른쪽 일정 칸) — 짧은 설계

앞선 [다크 리디자인](2026-11-24-dark-redesign-design.md)의 후속. 시안 3번(전체 재구성) 중 맥북 기준으로 실제로 구조를 바꿔야 하는 부분만 한다.

## 왜
"한눈에 보기 어렵다"는 불만 해소. 지금 오늘 화면은 일정과 할 일이 한 줄로 길게 쌓여 있어, 지금 뭘 해야 하는지 바로 안 보인다. 사용자는 주로 맥북(넓은 화면)에서 쓴다.

## 결정된 것 (사용자 선택)
- 맥북 기준: 사이드바 유지, 좁은 화면(<768px)만 하단 탭. 지금과 같다.
- 예정 화면은 날짜별 가로 열 유지(A안). 이미 새 디자인이 입혀져 있어 추가 작업 없음.
- 오늘 목록은 **우선순위로 묶고 묶음 안에서만 순서 바꾸기**(1번).

## 목표
- 오늘 목록을 세 구역으로: **기한 지남**(기존) / **지금 중요**(P1·P2) / **나머지**(P3·없음). 비어 있는 구역은 그리지 않는다.
- 넓은 화면(≥1100px)에서 구글 캘린더 일정을 본문 위가 아니라 **오른쪽 칸**으로 뺀다. 좁은 화면은 지금처럼 위에 쌓는다.
- 각 구역 안에서 드래그/Alt+↑↓ 순서 바꾸기가 지금처럼 동작하고 새로고침해도 유지된다.

## 하지 않을 것
- 오른쪽 칸의 작은 달력(시안에 있었음) — 새 기능이라 이번에는 뺀다. 필요하면 다음 작업.
- 수신함·프로젝트·태그·캘린더·예정 화면 구조 변경, 저장·동기화·알림 변경.
- 기한 지남 구역 안의 묶음(지금처럼 하나).

## 동작 변경 (사용자가 승인한 것)
- 직접 정한 순서(`sortKey`)는 이제 **같은 구역 안에서만** 의미가 있다. 우선순위를 바꿔 P1·P2 ↔ 그 외로 넘어가면 카드가 다른 구역으로 이동한다(순서는 새 구역의 기존 규칙으로 놓인다). 예전에는 우선순위를 바꿔도 위치가 유지됐다.
- 해당 e2e(`us16-list-reorder` 두 번째 테스트)는 새 동작에 맞게 고친다.

## 접근
1. **(선택)** 우선순위로 구역을 나누고 구역마다 기존 `enableReorder`를 붙인다. `todayView`의 정렬 결과를 `priority <= 2`로 나누기만 하므로 기존 정렬·저장 코드는 그대로.
2. 구분선만 표시하고 목록은 하나 — 직접 정한 순서가 우선순위보다 앞서 구역이 섞여서 제외.

## 디자인
- 구역 제목은 작고 굵은 보조색 글자 + 개수(`지금 중요 2`). 기존 `.section h3` 스타일 재사용, "기한 지남"만 위험색.
- 구역은 `section.open` 클래스를 그대로 가진다(기존 e2e 셀렉터 호환). 구역 구분은 추가 클래스(`.group-hot`, `.group-rest`)로.
- 넓은 화면: `.today-layout` 두 칸 그리드(본문 1fr, 오른쪽 280px, `min-width:1100px`). 오른쪽 칸은 `aside`(aria-label "오늘 일정")에 기존 `renderEventList` 결과.
- 오늘 화면 외 DOM은 바꾸지 않는다. 기존 클래스·`data-key`·aria 속성은 지우거나 이름 바꾸지 않는다.

## 검증
- 단위: 우선순위 분할 함수(`splitByUrgency`) — P1·P2 / 나머지, 순서 보존, 빈 구역.
- e2e: 구역이 맞게 나뉜다, 구역 안 드래그·Alt+↑↓가 유지된다, 우선순위를 바꾸면 구역이 옮겨 간다, 넓은 화면에서 일정이 오른쪽에, 좁은 화면에서는 위에, a11y(axe) 통과.
- 기준선: 단위 436, e2e 383 통과 상태에서 시작해 같은 수 이상으로 끝난다.

## 빌더에게 남김
구역 제목 문구 다듬기, 오른쪽 칸 sticky 여부, 빈 상태 문구 위치.
