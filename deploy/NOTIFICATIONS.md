# 알림(푸시) 설정과 확인

할 일에 기한 시각과 알림("정시", "30분 전", "하루 전", "당일" …)을 정해 두면, **서버가 그 시각에 기기로 푸시 알림을 보내요.**
앱이 닫혀 있어도 와요. 알림 문구에는 **할 일 제목이 들어가지 않고** "할 일 1건이 있어요"만 보여요(앱이 열려 있을 때의 앱 안 알림에만 제목이 있어요).

## 구성

- 서버 스케줄러가 **30초마다** 보낼 알림을 계산해 푸시를 보내요. 보낸 알림은 `reminder_log` 에 기록해 서버를 다시 시작해도 한 번만 가요.
- 서버가 꺼져 있던 동안의 알림은 **15분이 지나면 건너뛰어요**(푸시 TTL 도 15분). 이미 지난 시각에 정한 알림은 울리지 않아요.
- 알림이 가는 시각은 **각 기기의 시간대**로 계산해요. 시간대가 바뀌면 앱이 열릴 때 서버에 다시 알려요.
- 푸시는 외부 라이브러리 없이 직접 구현했어요(RFC 8291 암호화 + VAPID). 서버가 밖으로 내보내는 데이터는 이 푸시뿐이고, 구독 주소는 허용 목록(`web.push.apple.com`, `*.push.apple.com`, `fcm.googleapis.com`, `updates.push.services.mozilla.com`, `*.notify.windows.com`)의 `https` 주소만 받아요.

## 서버 설정

| 환경 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `TODO_VAPID_FILE` | `/var/lib/todo/vapid.json` (개발 중에는 DB 파일 옆 `vapid.json`) | 서버의 VAPID 키쌍. 처음 필요할 때 만들어 0600 으로 저장해요. **지우거나 바꾸지 마세요**(바뀌면 기존 구독이 무효가 돼요. 앱이 다음에 열릴 때 키가 바뀐 것을 알아채 다시 구독하긴 해요). |
| `TODO_VAPID_SUBJECT` | `https://todo.home.arpa` | 푸시 서비스에 알리는 연락처. 실제 이메일을 외부로 보내지 않도록 기본은 주소예요. 애플이 거절하면(응답 403 등) `mailto:` 나 다른 `https:` 주소로 바꿔 보세요. |
| `TODO_PUSH_ALLOW_HOSTS` | (없음) | **테스트 전용.** 로컬 가짜 푸시 서버(`host:port`)를 허용해요. 운영에서는 설정하지 마세요. |

`deploy/todo.service` 에 `TODO_VAPID_FILE` 이 이미 들어 있어요. 서버가 `*.push.apple.com:443` 등으로 **나가는 HTTPS** 가 막혀 있지 않아야 해요(방화벽에서 이 서버의 인터넷 아웃바운드가 허용돼 있어야 해요).

## 기기에서 켜기

앱 **설정 → 알림 → 이 기기에서 알림 받기** 스위치를 켜요. 브라우저가 알림 권한을 물으면 허용하세요. 기기마다 따로 켜고 끌 수 있어요.

- **iPhone·iPad**: Safari 에서 공유 버튼 → **홈 화면에 추가**로 설치한 앱에서만 켤 수 있어요(iOS 는 설치한 앱에서만 푸시를 받아요). 설치 전에는 안내만 보여요.
- 이 기기를 **홈서버에 등록**한 뒤에만 켤 수 있어요(알림은 서버가 보내요).
- 권한을 거부했다면 브라우저(또는 기기 설정)에서 이 사이트의 알림을 허용한 뒤 다시 켜세요.
- "테스트 알림 보내기"로 지금 바로 알림이 오는지 확인할 수 있어요.

## 서버에서 확인하기

```
todo-admin devices                  # 각 기기의 알림 상태(켬/끔/없음)
todo-admin push-test <deviceId>     # 그 기기에 테스트 푸시를 보내고 푸시 서비스의 응답 코드를 출력
```

`push-test` 의 응답 코드 해석:

| 응답 | 뜻 | 할 일 |
| --- | --- | --- |
| `201 (ok)` | 푸시 서비스가 받았어요 | 기기에 알림이 보이는지 확인 |
| `410`/`404 (gone)` | 구독이 만료됐어요 | 그 기기 앱 설정에서 알림을 다시 켜기 |
| `403`/`400 (fail)` | 키·형식 오류(VAPID 등) | `TODO_VAPID_SUBJECT`, 키 파일 확인. 서버 로그 확인 |
| `429`/`5xx (retry)` | 푸시 서비스의 일시 오류·제한 | 잠시 뒤 다시 |
| `응답 없음 (fail)` | 허용되지 않은 푸시 주소이거나 구독 키가 잘못됐어요 | 그 기기에서 알림을 껐다가 다시 켜기 |

## 배포 후 직접 확인할 것 (한 번)

이 기능은 **가짜 푸시 서비스와 RFC 공식 테스트 벡터로만** 검증했고, 실제 애플/구글 푸시 서비스에는 아직 보내 본 적이 없어요. 배포 후 한 번 확인하세요.

1. 아이폰에서 홈 화면에 추가한 앱을 열고 알림을 켠 뒤 `todo-admin push-test <deviceId>` 가 `201` 인지, 알림이 오는지 확인.
2. `403` 이면 `TODO_VAPID_SUBJECT` 를 `mailto:` 형식으로 바꿔 보기.
3. 2분 뒤 시각의 할 일에 "정시" 알림을 걸어 실제로 그 시각에 오는지, 알림을 누르면 그 할 일 화면이 열리는지 확인.
