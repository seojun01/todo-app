# 구글 캘린더 연동 설정

할 일 → 구글 캘린더 **한 방향** 연동이에요. 기한이 있는 할 일이 구글 캘린더의 **"할 일"** 캘린더에 일정으로 만들어지고,
수정·완료(✓)·삭제도 따라가요. 앱이 만든 캘린더만 다루는 최소 권한(`calendar.app.created`)만 요청해서
기존 캘린더는 읽지도 고치지도 못해요.

## 1. Google Cloud 에서 OAuth 클라이언트 만들기 (한 번)

1. <https://console.cloud.google.com/> 에서 프로젝트를 만들거나 고른다.
2. **API 및 서비스 → 라이브러리** 에서 **Google Calendar API** 를 사용 설정한다.
3. **OAuth 동의 화면**: 사용자 유형 **외부**, 앱 이름 아무거나, **테스트 사용자**에 본인 구글 계정을 추가한다.
   (게시하지 않고 "테스트" 상태로 두면 돼요. 단, 테스트 상태에서는 refresh token 이 7일 뒤 만료되므로
   설정 화면에서 "다시 연결하기"가 뜨면 한 번 눌러 주면 돼요. 오래 쓰려면 "프로덕션으로 게시"하세요.)
4. **범위(Scopes)** 에 `.../auth/calendar.app.created` 를 추가한다.
5. **사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**, 유형 **웹 애플리케이션**.
   **승인된 리디렉션 URI** 에 아래 `TODO_PUBLIC_URL` + `/api/gcal/callback` 을 정확히 넣는다.
   - 예: `http://localhost:8080/api/gcal/callback`
   - 구글은 `todo.home.arpa` 같은 내부 이름을 리디렉션 URI 로 받지 않아요. 아래 "홈서버에서 연결하기"를 보세요.

## 2. 서버에 설정하기

`/etc/todo/todo.env` (root:todo, 0640):

```
GOOGLE_CLIENT_ID=...apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=...
# 구글이 인증 뒤에 브라우저를 되돌려 보낼 주소 (리디렉션 URI 의 앞부분)
TODO_PUBLIC_URL=http://localhost:8080
# 연결을 마친 뒤 돌아올 앱 주소 (선택)
TODO_APP_URL=https://todo.home.arpa
# 시각이 있는 할 일의 시간대 (기본 Asia/Seoul)
TODO_TIMEZONE=Asia/Seoul
```

`sudo systemctl restart todo` 후 앱의 **설정 → 구글 캘린더** 에서 연결한다.
개발 중에는 같은 변수를 붙여 `npm run dev` 를 실행하면 돼요:

```
GOOGLE_CLIENT_ID=... GOOGLE_CLIENT_SECRET=... TODO_DB=./data/todo.db npm run dev
```

## 3. 홈서버에서 연결하기 (내부 이름만 쓰는 경우)

구글이 인증을 마치고 브라우저를 `http://localhost:8080/api/gcal/callback` 으로 되돌려 보내는데,
내 컴퓨터의 `localhost:8080` 이 홈서버를 가리켜야 해요. 연결하는 동안만 SSH 터널을 열어 두세요:

```
ssh -L 8080:127.0.0.1:8080 <홈서버>
```

그다음 앱(`https://todo.home.arpa`)의 설정에서 **구글 캘린더 연결하기**를 누르고 구글에서 허용하면 끝나요.
연결된 뒤에는 터널이 필요 없어요 (서버가 직접 구글과 통신해요).

## 4. 구글 일정 불러오기 (선택, 읽기 전용)

앱의 **설정 → 구글 캘린더 → 일정 불러오기**를 켜면, 구글 캘린더에 이미 있는 일정을 읽기 전용으로 가져와
**오늘·예정·캘린더** 화면에 할 일과 함께 보여 줘요. (할 일로 바꾸지는 않아요. 앱에서 고치거나 지울 수 없어요.)

- **권한을 한 번 더 허용**해야 해요: `calendar.calendarlist.readonly`(캘린더 목록)와 `calendar.events.readonly`(일정 읽기).
  Google Cloud 콘솔의 OAuth 동의 화면 **범위(Scopes)** 에 이 둘을 추가해 두세요. 이미 연결했더라도 설정에서 "일정 불러오기 켜기"를
  누르면 구글 동의 화면이 다시 떠요. 기본 연동(할 일 → 캘린더)의 권한은 그대로 최소 권한(`calendar.app.created`)이고, 읽기 권한은
  이 기능을 켤 때만 요청해요.
- 테스트 상태의 앱은 구글이 "확인되지 않은 앱" 경고를 보여 줘요. 본인 계정을 테스트 사용자로 추가해 두었다면 "고급 → 계속"으로 진행하면 돼요.
- **어떤 캘린더를 가져올지** 설정에서 고를 수 있어요. 처음에는 기본 캘린더만 선택돼요. 이 앱이 만든 "할 일" 캘린더는 항상 제외해요(중복 방지).
- **가져오는 정보**는 제목과 시각뿐이에요. 설명·참석자·장소·화상회의 링크는 요청하지도 않아요. 내가 거절한 일정과 취소된 일정은 건너뛰어요.
- **범위**: 오늘 기준 31일 전부터 366일 뒤까지, 반복 일정은 하나씩 펼쳐서 가져와요. 10분마다 자동으로 새로 받고, "지금 불러오기"로 바로 받을 수 있어요.
- **저장 위치**: 이 홈서버의 DB(`gcal_import_*` 표)에만 있어요. 기능을 끄거나 연결을 해제하면 불러온 일정은 지워져요.
- 시각은 `TODO_TIMEZONE` 기준의 현지 시각으로 바꿔 보여 줘요.
- 홈서버에 등록하지 않은 기기, 오프라인, 서버 오류에서는 일정만 조용히 비고 할 일 화면은 그대로 동작해요.

## 동작 규칙

| 할 일 | 구글 캘린더 |
| --- | --- |
| 기한(날짜)만 있음 | 종일 일정 |
| 기한 + 시각 | 30분짜리 일정 (시간대는 `TODO_TIMEZONE`) |
| 기한 없음 | 일정 없음 (기한을 지우면 일정도 지워져요) |
| 완료 | 제목 앞에 ✓ (처음부터 완료된 할 일은 만들지 않아요) |
| 삭제 | 일정 삭제 |
| 반복 | 현재 기한의 일정 하나. 완료하면 다음 날짜로 옮겨져요 |

- 캘린더에서 고친 내용은 앱에 반영되지 않아요. 앱에서 다시 수정하면 덮어써요. 캘린더에서 일정을 지우면 다음 수정 때 다시 만들어요.
- 구글 쪽 알림은 꺼 둬요(앱이 알림을 보내요).
- 연결을 해제해도 캘린더와 일정은 남아요. 다시 연결하면 중복 없이 이어서 동기화해요.
- 실패하면 멈추고 5분마다 다시 시도해요. 설정 화면에 마지막 오류가 보여요.
